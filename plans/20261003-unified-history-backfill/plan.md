## 运行成本与默认取舍

沿用现有模型链和预算，不增加逐篇人工审核或另一套通用评测。全量模型和必要的公开原文获取是用户已授权工作，缓存每条已完成输出；不为状态刷新重复运行模型。固定输入只需在接纳/变更边界校验，进度读取从已持久结果聚合，避免每次网页刷新重扫大文件。模型并发按共享 Gateway/部署容量决定，不能为了提高进度盲目扩大。

原文核验的自动化形式须在实施前独立核查既有契约与可复用逻辑，不能自行降低“完整原文”要求，也不能把 agent 先前加的机械人工步骤视作用户要求。若出现真实、不可兼得的取舍，先完成不依赖裁决的代码与验证，再明确交用户决定。

## 原实施决定（历史记录；原文核验部分已由上述用户修订替代）

在“扩展已有 backfill_runs/items”与“新建 campaign/第二套数据库工作流”之间，采用前者：全量原始输入一次性按规范身份分组入同一个 run，items 的 preparation 保存全部原始版本与准备结果，仍由现有 systemd timer 的 drain 领取。每条记录依次执行初筛、原文补取/核验、既有分析发布；准备阶段结果也进入同一条目的持久状态，原文核验通过前不得调用 articleFor 写文章。旧初筛目录按精确 key/inputHash/prompt/model 身份复用，新的初筛和后续步骤由统一执行器负责，不再并行启动另一个初筛执行池。

后台以全量 run 的同一个 items 集合呈现总数和逐日进度，旧试跑批次收起为诊断明细。每个身份一个条目，不另外维护由文件到进度快照的同步账本。个别失败不能阻止 run 中其余 pending 条目持续执行，只有已无可执行项且仍有异常时才等待处置。

材料索引由原始归档、已有 X 重建、源映射和已批准清单一次性生成，保存原始 key、日期、规范身份、候选材料及精确批准 hash；总数固定。先检查既有最终文章/批准结果，再读取已结算初筛决定。只有 BLOCK 算正常过滤；未结算模型错误不消费成内容判断。

实施 TODO T1：每个身份的唯一 UTC 归属日及选取依据随索引冻结；后续选择正文版本不改变任务归属日，保留所有版本日期，用同身份跨日版本验证总数与逐日口径。

缺少完整性证据时，由已批准的 DeepSeek 理解模型自动核验原文，输出 complete/incomplete/unverified 与根据，结果连同精确材料 hash、prompt 版本及回执持久化。已有精确 hash 证据直接复用。非 X 本地正文没有明确全文来源证据时，先补抓原网页；核验输入包含来源、HTTP 响应/提取上下文及实际正文，不能以“片段语义自足”代替完整文章。只有正文长度/非空、Readability 成功、结构化 fields 齐全均不构成批准。这个步骤替代逐篇手工审核的执行方式，保留原有完整性标准；HTTP/网络/提取失败及取回后仍不完整/不能判明的材料保留为具体原文问题，不记内容过滤、不造正文。X 保持既有核心文字自足标准；关键引用/媒体缺失仍保留待解决原因。

每一份审核结果只对本次材料 hash 有效；同一材料复用回执，使用独立 purpose/subject/promptVersion，不覆盖既有 understand_article 写作回执。新增审核调用最多每份本地材料一次、补取后的不同材料一次，已批准材料零次；实际代价先在原始样本上取 token/账本读数，再按剩余材料估算。本步骤是落实既有原文要求的自动执行环节，不改变评分标准。允许联网获取公开原文，不新增 Jina 或其它收费抓取服务。

实施 TODO T2：固定并保存核验 prompt 版本与实际模型参数；相同材料和判定身份只消费一次已结算结果，恢复不重抽样投票改变既有判断。

同身份多版本仍保留各版本的初筛结果；进入原文准备时优先复用已存在文章，未存在则以实际核验通过的确切版本入库，并保留选择的 key/hash/evidence。不同版本的 BLOCK 不传递给其它版本；只有各版本均为已结算 BLOCK 才将整条候选记为初筛过滤。全量入队复用 manifestHash 幂等、configure/resume 和已有插入保护，不覆盖旧文章。

单次执行有领取上限与在途结算边界，原文读取使用既有 guardedFetch 的 SSRF、超时和响应大小限制。已知未派发的预算/路由暂缺等待下轮；unknown 保留核账待办且不重发。准备业务结果与回执结算在同一数据库事务中落地，崩溃恢复依靠已有 manifestHash、回执身份和持久结果。正常终态与异常在同一个 items 状态中互斥，完成率只由终态驱动。

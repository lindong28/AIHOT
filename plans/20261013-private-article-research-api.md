## 目标与已确认取舍

用户希望通过自己部署的 news.aiplanet.live，查询指定公众号等来源的文章列表、搜索历史资料、获取每篇文章内容，并让自己的 agent 稳定调用。首个真实用例是“数字生命卡兹克”（账号来源 radar-mp-3223096120）。

2026-10-13 用户明确要求“就按照你的建议创建 plan。有需要我决策的就问我”，并通过提问工具确认：

| 事项 | 已确认选择 |
| --- | --- |
| 私有资料范围 | 保留资料，排除人工撤回或明确限制访问的内容；包括非精选、自动过滤但仍保留的资料 |
| 消费入口 | 私有 API＋现有 connector-workflows 下的共享 skill/CLI；第一版不需要私有 MCP |
| 验证档位 | 鉴权与受限内容访问 A2/V2；普通查询和客户端开发 A1/V1；未来生产发布另按 A2 执行。此确认仅规定计划中的保障范围，不批准实施或部署 |

完成效果：agent 可以按来源、关键词和日期找资料，遍历结果，按稳定资料 ID 或原文 URL 读取原文及出处。正文、生成摘要、译文与完整性证据有明确区分。“全部”仅指本服务实际保留且允许私有读取的资料，不代表公众号全网历史。

## 最小设计

### 资料与权限

增加独立的私有读取层，复用存储、URL 规范化和来源解析；公开出口继续使用 publication/ 的现有策略。研究令牌只授予读取能力，不授予后台管理、采集、回填或模型调用能力。

资料覆盖 articles 与在线 backfill_items 中仍保留、可识别的文章材料，不遍历服务器备份、日志或离线原始文件。按既有 URL identity 去重：已有关联文章时以当前 article 为主；仅有材料时使用稳定的独立命名空间 ID，并注明其材料身份、版本和出处。材料生成正式文章后，旧资料 ID 继续解析到同一资料身份；U2 固定转换前后读、分页和去重的连续性。多个版本的材料不得绕过同一 URL/身份的当前人工限制，也不得冒充多篇文章。

人工 withdrawn 排除；人工 summary-only 的正文不参与匹配、计数、摘要提取或排序依据，也不返回正文或正文命中片段；其他明确访问限制按其语义落实。自动 filtered、未精选与人工撤回分别处理。site_fulltext、syndicate_fulltext、participation_mode 的公开展示语义不直接等同私有权限，不更改原有公开许可。U0 核对状态的真实写入来源和适用范围；发现无法据已有决定判定的权限冲突时，由执行者带具体记录与影响交用户决定，再推进受影响部分。

公众号按当前账号身份及可核实的历史归属汇总；保留真实采集 source_id，不重写旧文章归属。复用唯一作者匹配及微信 URL 证据，名称重复或身份不明时不猜测合并，未知归属仍可独立检索。账号显示身份与采集身份分别表达。

### API 与返回语义

建议使用独立命名空间 /api/private/v1；最终字段、错误结构和示例随实现写入同一份私有 OpenAPI 定义，CLI 消费该契约。

| 能力 | 建议入口 | 结果 |
| --- | --- | --- |
| 找来源 | GET /sources | 按名称、类型查账号或来源，取得稳定查询标识 |
| 列举与搜索 | GET /articles | 按账号、关键词、起止时间、是否精选过滤，游标分页；列表返回元数据和匹配摘要 |
| 读资料 | GET /articles/{id} | 已保存原文、来源、原 URL、时间、版本、可用的完整性证据；支持 JSON 和 Markdown |
| 原文定位 | GET /articles/resolve?url=... | 规范化后查本库资料；不向输入 URL 发请求 |

列表时间默认为发表时间，缺失时回退发现时间并注明依据；按该时间和稳定 ID 确定顺序。游标绑定查询条件、排序与查询截止时间，开始之后新增资料留到下一轮；不承诺数据库事务快照。翻页期间撤回、清除或修订按当前权限处理，客户端须能识别这一变化，不能将变化后的计数冒充固定快照总量。

详情明确原始标题、已存原文、生成摘要和译文的边界，携带原 URL、来源、时间及可用 revision/content hash。完整性采用已有证据；未知仍可读取，但标明未知，不以字数或非空判完整。不静默截断；如需分段，返回明确续读信息并绑定版本，版本变化时可重新开始。已清除、缺正文、正文不完整、无完整性证据分别表达。限制记录与不存在记录的错误不得泄露被拒绝内容。

### 鉴权与调用

专用只读 bearer token 经 HTTPS 使用；未配置时私有接口关闭。服务端验证令牌摘要，支持撤销和轮换，现有 admin/ingest 凭据不能代用。令牌不进入 URL、前端、文章内容、示例、日志或普通 Git 文件；沿项目已授权的 secret carrier 配置，新增密钥落点须另获授权。AIHOT 不提交 .env。

列表、搜索片段、详情、URL 定位和历史材料共用访问判定。私有响应 no-store，反代/CDN 不缓存私有内容；不开放不必要的跨域读取，客户端重定向不转发凭据。日志只保留排障所需身份/状态，不记录令牌或正文；复用现有运行监控入口，按服务失败面核对是否需补最小信号，不新建独立监控系统。

### 搜索与客户端

第一版提供标题、生成摘要、完整原文的关键词检索，支持中文，并注明命中位置。先沿用 PostgreSQL，在隔离代表数据上验证直接索引和查询；仅当必要时加入最小私有投影，覆盖未公开及材料独有记录。索引不截断原文，随入库、revision 和保留清理更新；返回前再次核权限。首次构建分批可恢复，不改原文、不触发模型。读取请求不重建索引。

分页、响应体和并发受有界参数控制；用实际查询计划、代表数据与现有服务容量确定参数，沿用项目现有负载保护，不自行增加 SLA。批量读取采用容量内有界并发，不将生产 DB 当性能测试环境。

AIHOT 仓拥有服务端和 API 定义；ai-agent-config 的 connector-workflows 拥有调用说明及薄 CLI，提供 sources/search/read、游标续读和按需保存 JSON/Markdown。不复制服务端权限与身份算法；失败、中断、截断或权限排除时不能宣称取全。两个 harness 共用同一实现与凭据约定。

## 实施顺序、状态与验收

执行者负责以下全部可自动化工作；用户负责真实范围、权限取舍与另行发布授权。当前 U0 为部分基线已取，U1–U5 均未开始。

| 单元 | 依赖与交付 | 验证与退出条件 |
| --- | --- | --- |
| U0：补齐数据与状态语义 | 在隔离副本或有界数据分片盘点文章/材料、去重、账号映射、人工与自动限制；确认查询字段和已存正文证据 | 给出独立预期身份清单及权限真值表；生产 JSON 聚合超时不以增加线上扫描预算解决。语义冲突才交用户 |
| U1：最小私有读取链路 | 依赖 U0；令牌鉴权、来源查找、正式文章列表与详情，复用原文转换 | 用真实 HTTP 客户端完成“找账号→翻页→读原文”；未授权、错误令牌与受限内容均拒绝，访问边界按 A2/V2 |
| U2：全保留范围与检索 | 依赖 U1；加入材料独有记录、身份去重、关键词/日期过滤、完整正文索引、稳定分页 | 原材料与文章集合对账；正文尾部检索、多页、修订/撤回变化和限制旁路用例通过；权限部分继承 V2，其余 A1/V1 |
| U3：共享 agent 入口 | 依赖 U2；connector-workflows 的 skill/CLI 与安全配置读取 | 通过 CLI 运行真实 API 的来源→搜索→读取→保存流程，验证分页结束与不完整输出报告 |
| U4：本地交付 | 依赖 U3；接口说明、部署/轮换说明、使用示例和必要回归 | 单轮独立审查及项目要求检查；完成自有提交、本地主线整合，报告未验证部分 |
| U5：授权后发布与实用验收 | 依赖 U4 和明确生产部署授权，生产动作按 A2，访问安全验收继续 V2，其余验证依实际发布影响确定；核 outgoing commits、发布基线及线上配置 | 固定本次发布 SHA，经生产 API→CLI 复验真实读取、鉴权及公开出口兼容；失败按已准备回滚方案处理 |

最小真实消费者路径是 U1 的“带令牌列该账号并读一篇正文”。身份与访问策略是这条路径必需的前置；完整检索索引、共享客户端封装和额外监控不阻塞这次早期验证。U1 可用不代表 U2 的全量范围已完成。

用户结果验收：

1. 在固定隔离数据集上，通过 CLI 列出目标账号资料，与独立 DB 预期身份集合比较，差集为空且无重复；覆盖当前来源、两个历史来源、材料独有记录和未知归属对照。上线时刷新基线，108 不是永久常量，也不包括尚未盘清的材料。
2. 获取正文时，对照已存原文的首尾、长度/内容摘要和版本，证明传输没有静默截断；这不替代原网页完整性评估。有/无完整性证据均应准确表达。
3. 用中文词、日期边界、超过 12,000 字且独有词仅在尾部的样本验证关键词查询；覆盖多页、新入库、材料转文章及旧 ID 解析、翻页期间撤回/修订，不以总数相同代替身份一致。
4. 无令牌、错误令牌、已撤销令牌不能读取；人工撤回、summary-only 的正文限制不能通过正文关键词命中/计数/排序、片段、直接 ID、原 URL 或旧材料副本绕过；正常可读对照仍成功。
5. 查询不启动采集、模型或任务；公开网站、公开 API、RSS、MCP 继续遵守原有发布和全文规则。真实消费端验收不能只用单元测试或 HTTP 200 代替。

内部检查沿 [AGENTS.md](../AGENTS.md)：typecheck、空隔离库迁移和 npm test、Web build 与 Web tests，启动隔离站点后 smoke。权限边界做一次独立审查和覆盖其状态的越权验证；普通查询与 CLI 沿已确认 A1/V1 检查，不扩建评测体系或无依据增加审查轮。现有 docs/contracts/ux-contract.md 不存在，不为本任务预建。

## 决策依据、未决项与后续记录

选择独立私有读 API，而非扩大匿名 site API 或复用管理员会话：前者承载公开阅读策略，后者携带不需要的管理权限。直接数据库脚本会让消费者获得数据库权限并复制策略。共享 CLI 已由用户选择；第一版关键词检索直接服务本目标，不预建向量库、私有 MCP、管理 UI，也不改内容保留、自动重采集或付费分析策略。

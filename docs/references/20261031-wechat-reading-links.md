# 微信采集地址与阅读地址

2026-10-31 决定：保留采集 URL、文章 identity、去重与 docId；以已有 identity 为归属，增量保存经过原页正文及四参数核对的分享地址。独立决定审查一轮放行，实施后独立审查及定向修复复核完成。生产验收另记，本段不宣称已上线。

已知案例是《Grok Bot 玩法 02：躺床让它帮你做视频理解复杂概念》：原浏览器在 2026-10-31T04:47:27.109Z 读到正文，窗口中的 biz/mid/idx/sn 与已存采集地址一致，msg_link 和 og:url 均为 `https://mp.weixin.qq.com/s/1afnn-WeU4KvD03lqSIv2w`。同浏览器访问采集长地址出现微信验证页。这只能证明当次访问结果不同，不能证明微信改过链接、AIHOT 记错身份或短地址永不触发验证。

独立表 `wechat_reading_links` 覆盖 article 和 material-only 身份。登记与入库在同一事务中锁定别名并核对既有归属；冲突拒绝、相同映射不重复写入、不自动合并历史身份。历史正文、原始地址、内容 revision/hash、冻结回填清单与旧发布快照保留。

已经需要直接补正文的采集请求可从同一响应提取链接；完整 RSS 正文不增加原页抓取。普通采集 JSON 不能自行声明链接已核实。既有浏览器证据通过具备数据库权限的操作者显式确认，离线 CLI 默认预览且不访问微信。缺正文、验证码和矛盾元数据不登记链接；元数据不足不丢弃有效正文。

网站、公开 API、RSS、报告引用和精选变更账本使用共同阅读投影；只改变原文链接，不重跑模型或重发内容通知。私有 v1 保留原输出形状及采集 `url`，v2 增加可空 `readingUrl`；两版 resolve 均可读取已登记别名，保留权限拒绝和 fragment 身份优先。共享客户端默认 v2，可显式选 v1，不把任意 404 当版本不支持。

未登记且没有证明的短地址与长地址不能判断为同篇。本轮不全量追抓、不更换微信出口、不新增真实微信验证；验收复用上述原始观察，并以隔离 HTML、PostgreSQL、HTTP 和正式 AIHOT 消费者验证实现。

运维入口 `scripts/verify-wechat-reading-link.ts` 默认预览，只接受持数据库权限的操作者显式确认已经取得的浏览器证据。用法见 [登记已经核实的微信阅读链接](../operations/wechat2rss.md#登记已经核实的微信阅读链接)。它核对证据结构和指定目标，不冒称新的网络验证。重复相同映射保留首次证据；中断后先预览再决定重试。新表随身份保留，只保存链接、观测来源及校验锚，不复制正文或凭据，不新增定时任务。

未采用直接改 URL/identity、article 单列、仅前端替换、文件映射或全量追抓：分别会扰动既有身份、遗漏仅材料资料、遗漏机器出口、失去数据库事务边界或增加未经要求的微信请求。迁移与正式消费者验收另记于本次发布记录。

本地验收使用 Node 26、PostgreSQL 17 全新隔离数据库，52 份迁移应用成功；后端 495 项通过、2 项既有跳过。11 项阅读链接测试覆盖长短链接先后及并发入库、仅材料晋升、重复／冲突登记、两版私有接口权限、公开出口、片段身份、必要抓取及发布门禁。审查发现的章节误合并与并发发布恢复长链均先取得失败读数，再修复通过；普通发布在取得 article 锁后用新语句读取链接，避免等待锁前的旧快照。完整 RSS 与已修正文的别名读取在隔离 HTTP 测试中没有新增微信请求。既有未来发布 fixture 的全局水位影响只在 ledger 测试时钟处理，生产时钟和门禁不变。

# 全量历史的原文前初筛

读者：维护者与开发者。2026-10-03 用户在获知原文前初筛可能遗漏仅在正文出现的 AI 信息后，明确选择“先初筛再补原文”。本记录改变准备阶段的顺序，原生导入的完整原文要求保持有效。

## 执行与恢复

`scripts/backfill-prefilter.ts` 复用原生 `runPrefilter`、Qwen 绑定和 `backfill` 预算回执。只有 BLOCK 版本终止；PASS、UNKNOWN 进入待补原文。仅标题或聚合卡片没有独立内容时直接待补原文，label 与 receiptId 均为空，不伪造模型结论。不同原始版本独立处理，某版本 BLOCK 不排除同一旧 ID 的其它版本。

原始输入 SHA、promptVersion、模型绑定及运行环境写入冻结 manifest；更换输入或语义配置会拒绝沿用结果目录。输出路径、时间和进程号不加入模型调用身份。模型输出先持久化，再在短事务中锁定回执，只把 received 结算为 completed。unknown 不能由文件缓存覆盖，也不自动重发。累计执行错误写入 summary，继续其它条目但返回非零；预算等待另列，不是内容失败。

准备阶段只检查 Qwen 的实际可用性，不要求尚未调用的 DeepSeek 角色就绪。评分、理解和摘要继续采用已批准的 DeepSeek V4.1 Flash 腾讯绑定；本工具不调用这些角色，不插入文章或发布内容。

## 调度边界

可选的 `deploy/production/backfill-preparation.conf` 接在同一 oneshot service 的 native drain 后，避免两个执行池叠加。准备并发 8 指单次预筛请求；原生并发 8 是文章 worker 数，结构与评分可能并行，不能称全链路最多 8 个模型请求。

每轮准备最多领取 400 条；90 秒是从首个待处理项开始的领取窗口，扫描已有结果和输入验证不包含在内，到时等待在途请求结算。服务启动上限 50 分钟、停止等待 10 分钟。原生内容理解显式 timeout 180 秒，经 Gateway 后尾调用可等待 560 秒；准备尾调用可等待 440 秒。`1500+560+90+440=2590` 秒不包含预检和文件／数据库操作，不是严格的运行总上界。

既有 Mac probe 读取生产固定准备目录的 summary，未解决错误跨轮持续报告；状态丢失不作为恢复证据。内容 BLOCK 是正常筛除，不进入“失败待处理”。准备错误与原生批次错误分别记录。

## 分母与验证范围

全量离线输入有 167,150 个旧记录 ID、170,160 个 ID/hash 版本。已批准的 243 个原生身份覆盖其中 294 个版本，准备输入余 169,866 个版本。直接调用原生材料判据核对全量输入后，109,199 个版本缺材料，60,667 个有材料可初筛。单独统计 excerpt 为空会得到 126,233，但其中 17,034 个 X 版本仍有原帖或引用文字，不能称为“仅标题”。输入 SHA256 为 `96e264bd65c91033367d129190b4e9fa3509bdfe84c0a8e1ef8b3dafce775879`，原始归档和转换核验保留在主 checkout `.data/history-batches-20261002/`。

上述数量来自离线库存核验，不是批准、导入或发布数量。准备阶段的 filtered / needs_original 不并入后台原生完成数。更早筛选的实际收益、召回与全量耗时只能由后续运行衡量；本决定没有声称与全文筛选等价。设计经一次独立审查放行，实现与生产验收另行取得读数。

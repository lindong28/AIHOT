# 公众号按账号接入

2026-10-04，用户要求更新线上链路，加入旧 AI RADAR 读取的公众号，数据结构基本参照 Twitter。独立 decision-review 一轮及历史语义窄复核放行，代码审查一轮放行，线上验收如下。

## 决定与范围

复用 Mac mini 现役 Wechat2RSS，每个订阅登记为独立 `mp_account`。`provider=wechat2rss` 选择采集器，`bizId` 是公众号身份，`feedId` 是上游 RSS 寻址；名称由来源记录提供。文章进入既有 `articles`、URL identity、发现记录、处理队列与事件来源计数，不增新表，不借用 `x_post` 的推文专有字段。站内和 RSS 全文展示继续关闭。

由 Mac mini 专用 launchd 隧道把现役 8080 转发至腾讯云回环 39033；不改旧容器、登录和采集。部署私有环境提供 `WECHAT2RSS_BASE_URL`、`WECHAT2RSS_RSS_TOKEN`，来源配置不存 token。新 provider 仅允许部署指定的 HTTP IPv4 回环 origin，固定路径、禁止重定向、有超时与响应体上限；全局 SSRF 防护保持。

未选聚合 RSS：现役聚合输出只有 50 条，且合并公众号身份。未切 Dajiala：需要另一供应商及按次费用。未以服务搬迁为前置：本次需要接通公众号，原 Studio 服务迁移仍未完成；不改变该迁移任务的结论。

首轮最多 8 条，固定接收下界为首轮时间减 7 天，后续检查可以补齐这个窗口内的剩余内容，不滚动提高发布时间下界。初始化前文章标记 `first-import`，沿用统一时间规则：超过 48 小时或无日期的历史不建当前事件和热度，近期首采仍可参与。8 条不是整个启动阶段的总上限。RSS 保留窗口外的中断缺口不自动回填。

主线程实测原服务 22 个未暂停订阅、2,220 篇文章；22 个逐账号 RSS 均返回文章、作者、日期与正文。量子位 feedId 路径返回 200，bizId 路径返回 404；Mac mini 至腾讯云 SSH BatchMode 认证成功。生产原有 RSS 40、X 109、网页 10、JSON 4、external 16，尚无 mp_account。上述是接入前快照，不是生产处理或发布验收。

现役旧服务和探针不变。新增隧道的外部可达性告警尚未验收，由 AIHOT 维护者在本仓公众号运维待办承接。回退可暂停新增来源、停止自有隧道、切回旧 release；已经入库的文章、发布结果和模型费用保留，代码回退不撤销这些副作用。

审查已修正一项决策增量：不得把 `first-import` 宣称为一律不参与热度。其余七判据成立，无未消解项，无基线独立 finding。审查来源：原生独立 agent `wechat_decision_review`，基线 `bc9114d`。

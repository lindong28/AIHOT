## 决定与边界

保留 receipts / receipt_attempts 原始请求、响应、usage、cost，以按 receipt_id / attempt 绑定的 receipt_reviews 记录处置。核账（未知、已计费、未计费）、停止、明确授权重放分开；核账和停止不调用模型。当前 attempt 的停止、业务结案或明确拒绝阻止同一逻辑请求再次派发。修改输入产生的新逻辑请求不受旧处置影响。

明确审核拒绝包括安全错误分类与保存响应的 content_filter / refusal；明确请求拒绝仅接受 invalid_request 且 HTTP 400 / 422。能力协商的空 HTTP 状态不属于明确拒绝。拒绝不证明任何历史 provider attempt 未执行或未计费。保留真正未知的 timeout，不为清空列表重放。

业务结案必须匹配目标、当前版本及当前 attempt；时间下界使用被处置 attempt.started_at，缺失不结案，不能用 receipt.created_at。digest 结案核对当前 stories.version、对应持久化 story_digests 和已完成回执。既有 batch 的相同时间缺陷一并修正，保留后续失败保护。

后台使用全量聚合和分页，提供待处理、已处置历史；告警复用待处理语义，不再声称所有未知请求都重试过一次。错误保留安全类别、Gateway 固定错误码与输出截断原因，不保存自由上游错误或敏感请求。综述在既有生成次数和 token 预算内增加精简反馈，不截断接受不完整正文。

不选直接修改 unknown 为 failed（会隐式放行重付），不扩展主回执枚举，不只改标签。继续采用 PostgreSQL，新增表只保存异常处置和审计关联；不保存重复响应，不设删除账本历史的清理逻辑。不改模型、provider、路由、并发或预算。

历史依据：10/02 未派发核对、10/04 业务结案与安全错误、10/07 recovery v1 文档。独立审查七项通过，纠正了 invalid_request 分类过宽和 receipt 创建时间掩盖新失败两处边界。资金与账本路径按 V2 验证正常、拒绝、并发陈旧操作和失败路径；部署为 A2，独立审查与固定版本发布。页面等生产行为按 V1；不增加整体评测平台。

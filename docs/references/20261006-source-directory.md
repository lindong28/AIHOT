# 按来源浏览新闻

2026-10-06 用户确认两级来源目录设计，并要求写入仓库后实现、验证和部署。本页记录该功能的用户体验与实现边界；上线验证另在文末追加。

## 页面与入口

桌面导航在“主题”旁增加“来源”，手机通过“更多”进入。`/sources` 标题为“按来源看 AI”，提供按名称、账号或域名搜索。沿用主题页的色彩、紧凑卡片、字体与间距，不新增一套视觉系统。

第一级按读者认识的平台分为微信公众号、X、Hacker News、网站与博客、开发者平台。微信公众号和 X 的第二级为具体账号；网站与博客显示媒体或博客，开发者平台显示项目或组织。Hacker News 点击后直接查看该渠道新闻，不制造没有意义的第二级。采集器名称与内部运行信息不出现在目录中。

各分类有“查看全部新闻”入口。账号卡片显示头像或名称首字、名称、可辨识的账号或域名、公开新闻数；没有公开新闻的当前来源仍列出，显示“暂无公开新闻”。目录完整列出当前启用的非隔离来源，不使用首页的抽样来源清单。

## 分类与账号新闻页

分类页显示该类全部公开新闻，并提供可搜索的账号列表。账号页显示“来源 › 类别 › 账号”面包屑、名称和标识。默认“全部”，可切换“精选”；列表按时间倒序，沿用新闻卡片、日期分组与分页。筛选和页码进入 URL，可直接分享并通过浏览器返回恢复。手机使用单列与折叠搜索列表，避免铺满账号标签。

新闻卡片与详情页的来源名称链接到对应站内来源页；“阅读原文”继续直接打开原文，两种行为在文案上分开。Hacker News 仍注明原发布网站与发现渠道，不把投稿人当成作者。

## 数据语义

数量只计入列表中实际可访问的公开新闻，精选延迟与撤回条件同样生效。同一公众号或 X 账号的实时、历史回填文章汇合到同一个页面。身份无法确定的历史微信公众号文章留在一级分类中，标注“账号未识别”，不猜测账号，不公开聚合采集器名称。停用来源的既有公开新闻仍可访问，历史来源与当前接入来源分开标明。

不改变采集身份、去重、评分、热度参与和全文许可。读者访问这些页面不触发模型或抓取。前端仍只通过站点 API 访问后端统一公开读取层。

## 验收

从导航进入目录，搜索账号，分别打开类别与账号列表，切换精选、翻页、返回目录；从新闻卡片和详情来源返回对应来源页，原文入口保持原有行为。桌面与手机检查上述路径、空列表和零新闻来源。用数据库用例核对当前与历史账号汇合、未知归属、撤回/延迟/不符合公开资格的排除，以及目录和新闻计数。先本机验证，再部署腾讯云 API 与 Web，并复验公网入口。

## 实现决定

独立 review-decision 七项成立后放行：保留采集 source_id，在 publication 读取层统一派生来源路径，供目录、计数、筛选与文章 source.href 使用，不新增持久分类投影。X 以合法原帖 URL 的小写账号为身份；公众号沿用原生账号 ID，两个已知历史聚合仅将作者唯一匹配到非隔离公众号（包括停采账号），未知身份回退类别页。其它网站和项目沿用配置的来源身份。后台配置只参与解析，公开 API 不返回配置、采集地址或凭据。

Hacker News 是发现渠道，与发布者类别不互斥：它收录的 X 原帖同时进入 HN 渠道和 X 账号页，文章 source.href 指向账号页。类别计数不可相加当作去重新闻总数。默认列表按既有 timeline_at 倒序，沿用公开资格与精选发布时间门槛。停采历史来源仍可从类别和文章进入，目录默认只列当前来源。

不采用直接按采集 ID 筛选（不能汇合历史聚合）、重写文章 source_id（会改变业务身份），或新增实时/回填/存量同步的持久分类（本次只读派生即可满足）。该决定仅覆盖网站来源导航和站点 API；落盘时实现、性能、UI 及生产尚未验收。

`npm run typecheck`、Web build、Web tests 11/11、相关后端 tests 24/24、本机 smoke 通过。后端样本覆盖原生/历史公众号、未知与歧义作者、原生/历史 X、转帖与 HN 交集、零新闻账号、撤回/延迟/不符合资格、40/41 条分页边界、停采详情和不存在账号。Web tests 为仓库现有路由、缓存、取消等用例；视觉和交互另用隔离 headless 浏览器检查桌面 1440×1000、手机 390×844。实际走通目录搜索、分类、账号、全部/精选、零新闻、账号选择器搜索、翻页、返回和详情来源链接，原文链接仍单独存在。

## 生产部署与验证

部署目标为腾讯云 `/home/ubuntu/aihot/releases/source-directory-20261006`，从原 `report-images-20261006` 复制并覆盖本次文件，保留环境配置和数据库。源码基线核对中仅文档落后于本地既有提交，已补齐；运行代码基线一致。构建后切换 `current` 并仅重启 API/Web；worker、Wechat2RSS、回填与模型配置不变，无数据迁移、存量回写或模型重跑。

公网目录 `/sources` 识别出当前 31 个公众号、109 个 X 账号、50 个网站与博客、3 个开发者平台来源，另有 Hacker News 渠道（2026-10-06 快照）。公网 smoke 通过；真实浏览器走通桌面目录到量子位账号、新闻详情及来源返回，手机“更多 → 来源”和搜索。各类 API 返回公开新闻，量子位账号同时呈现实时与历史文章；公众号原文入口仍为“阅读原文”。

生产数据下预检发现来源解析重复计算：初版公众号分类页后端读取 5.29 秒。优化仅做等价查询简化：X 主机先筛后完整验证 URL，分类路径取第三段比较，all 页复用同次目录总数，非 X/HN 分类先筛来源表，再执行完整文章身份条件；不新增陈旧缓存。独立差分审查与相关回归核对分类语义，最终公网耗时另附实测值，不以单次读数承诺所有请求延迟。

最终公网采样：手机从搜索结果点击 OpenAI 账号到页面标题更新为 3.77 秒（实际 click 事件至 DOM 变化，n=1）；量子位账号 API 3.52 秒、开发者分类 API 3.29 秒（各 n=1，串行测量，含本机到公网往返）。这些是三个不同入口的一次读数，不是延迟分布或高并发结论；冷访问仍可能等待数秒，未宣称秒开。继续优化需衡量全目录实时聚合成本，本轮不增加持久投影或扩大缓存时效。

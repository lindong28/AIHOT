日期：2026-10-07。范围：本地开发与验收；不切换生产、不 push。基线：`f69fd1f`。用户要求先记录设计，再按设计实现。

## 决定

以事实级身份、保守结构化兜底和同事件日期归属适配上游主题大事记；复用月度选材与 UI，支持公开资格检查后的人工历史，不触发模型或历史事件写入。人工历史与近 12 个月自动精选分别说明；兼容年月日精度和可选单一链接。

上游移除前快照为 `cc66cceb1dc7a0bc147e942e49ff94c9cee418c6`。复用其 `Chronicle.tsx` 的公司横轴和方向／形态纵轴，以及行业规则与 publication 读取层分离的结构。原函数的合成反例已显示：同 story 的模型发布与 API 开放被合为一个节点且标题日期错配；DeepSeek V4 与 MiMo-V4 被误合并；Flash/Pro 大小写改变合并结果；有视频标签的 Seedance 发布被标题关键词排除；发布标题附带免费使用或后续预告导致整条被否决。因此不直接移植旧身份与标题算法。LLM 重写引入额外调用且没有必要；只移植 UI 不能满足选材正确性。

独立 L1 设计审查：七项最终为成立／不适用／成立／成立／成立／成立／成立，放行。首轮指出人工历史时间文案和旧 JSON 精度边界，已按下面内容收口；实现与真实准确率尚未验证。

## 数据与算法

1. 只从 publication 读取当前公开、已释放、eligible、selected 且来源为 editorial 的文章。沿用主题标签成员规则，方向主题不再额外要求标题关键词。历史回填的分析结果也可参与，但不创建 fact、story、热度或任务，不调用模型。
2. 有仍有效的非 mention `fact_articles` 关联时，以 fact 身份作为节点；story 只用于导航，不用于去重。没有 fact 时，仅主体、动作、完整对象、明确发生日全部齐备且规范化后相等才合并，否则保留 article 身份。规范化只统一大小写、Unicode 和空白，不去掉厂商、系列、版本或变体。不做名字相似合并。
3. 节点日期优先采用本事实有效发生日期，否则采用同节点最早公开报道的发布时间，再回退 timeline。无效日期回退，未来发生事件不入选；不得用另一个 fact 的日期搭配标题。近 12 个自然月含本月，以北京时间划界。
4. 模型、产品、研究、公司、行业类型由现有分类与标签决定。公司主题使用事实主体／分析主体解析行业实体词典；无主体时只接受唯一实体标签，明确其他主体不能由标题猜回本公司。已知教程、评论、合集和未发生动作不作为发布。标题负面筛选限定主句，避免附带“免费开放使用”或“并预告……”误伤真实发布；显示原标题，不猜写简化事件名。
5. 保留上游默认门槛：公司模型 70 分、每月 3 件，产品 75 分、2 件，公司新闻 85 分、1 件；方向／形态模型、产品、研究 75 分，行业 85 分。后者每月共 5 件，model-releases 为 8 件。依次比较分数、不同来源数、第一方、日期与稳定 ID。门槛是未经本项目样本校准的初始值，不声明准确率或完整覆盖。
6. 公司可选 `industry/chronicles/{slug}.json`：`topic`、`through: YYYY-MM`、`events`。事件支持 `date: YYYY / YYYY-MM / YYYY-MM-DD`、`kind`、`title`、可选 `summary`、`major`，以及 `story / item / url` 至多一个、可无链接。按给定精度验证真实日期，不补造日期；外链限 HTTPS。人工记录截至 through，当月及更早的自动节点不再补入。内部 story/item 每次读取复核当前公开资格，不可公开的条目不输出；外链和无链接条目属于人工维护，不声称经过数据库核验。无文件时正常只读自动节点。

## API 与页面

主题详情增加 `chronicle` 投影：类型显示定义、按月自动节点、公司历史节点与是否包含人工历史。仅第一页读取和显示；没有节点不显示空模块。精选／全部两种列表范围保留原行为，大事记始终取精选，并明确说明范围。

公司用可横向滚动的双轨时间轴，最新端默认可见；有人工历史时说明“人工整理历史与近期精选进展”，另注明自动部分近 12 个自然月。方向和形态用月份纵轴，默认最近 5 件，可以展开更早节点。链接保留公开阅读入口，键盘和移动设备可以操作。

不引入数据库迁移、持久投影、缓存层或后台刷新任务。读取先收窄主题及时间候选，再在纯函数中归并与选择；事实成员资格随当前状态检查。
